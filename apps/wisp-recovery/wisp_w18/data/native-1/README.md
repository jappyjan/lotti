# native-1 (NOT pinned)

The MVP image for the left temple (docs/wisp/rung4.md, "W25: native-1 (MVP)"): the observe-only Wisp Boot with the W24c fixes (half-duplex case UART, MSPICFG's resets kept, the record and status block cleaned from the D-cache, the hardened hand-off) and the full Wisp app at `0x448000`: no console, the watchdog fed from a timer while the PMIC thread lives, breadcrumbs and a fatal-error handler in Wisp Boot's record, the half-duplex case UART (IDENT, READ blocks 1, 2 and 4, BOOTREP, RESET), BLE with the Wisp GATT service and a wisp-core session, and the boot screen on the JBD4010 through the gated rail switches. MIT, our own code; nothing of Even's.

**Not pinned.** `wisp_w18/pins.py` does not list it, so `install-wisp` refuses it (`tests/test_native1.py` checks that, and that the whole gate accepts these files once they are pinned). Pinning is a separate, reviewed step, as W23 and W24b-0 were: an independent review of these files and the tree they were built from, then `pins.WISP_IMAGES["native-1"]` (image, stripped ELF and map hashes, both gates, `crc32`) and its Wisp Boot slot in `pins.WISP_BOOT_PASSED` with both observe suites (rung4.md W25, "Evidence"). The review must also give Jan's go for the four new PMIC task writes (the panel's rails, rung4.md W25).

| File | What |
| --- | --- |
| `native-1.bin` | the image: Wisp Boot padded to 64 KiB, then the app at `0x448000` |
| `zephyr.map` | the app's linker map, as built (it holds the build checkout's absolute paths, so it is pinned as built) |
| `zephyr.elf` | the app's ELF after `arm-none-eabi-objcopy --strip-debug` (gcc-arm-embedded 15.2.rel1 from the wisp-fw flake) |
| `wisp_boot.elf` | Wisp Boot's ELF, `--strip-debug`; the Renode harness takes its milestone addresses from it |
| `manifest.json` | the build's own manifest (image, Wisp Boot binary and slot, app binary, unstripped ELFs and maps: SHA-256; the image's CRC-32; the gates that ran) |

The image: **`69ca31bfd61e1580ae3ca3bb036423c4dad0b56d7cad42be424751c22637701a`**, 245,148 B, zlib CRC-32 `51d1d00b`, ending at `0x473d9c`; Wisp Boot `wisp_boot.bin` `2387b1b95103734a…` (12,048 B, the W24e/stage-0c Wisp Boot: MSPI1 powered and its IO clock ungated, `nor_off` before the hand-off, full NOR phase), slot `f24e887078eebf17…`; the app `7d75e34e11ab9f9d…` (179,612 B). Built from commit `28afba8` (the app reports that revision) at the checkout path `/home/jappy/.t3/worktrees/lotti/t3-c843265c` (the map records it; reproduce at that path with the `unshare` bind mount of `data/stage-0b/README.md`). The SHA-256 of every file is in `manifest.json` (the ELFs there are the unstripped ones). Built on t3-worker with `apps/wisp-fw/scripts/build_native.sh native-1` from a clean, committed tree and copied here by `scripts/package_native.sh native-1`. The build's gates: `check_image` (Wisp Boot and `--part app`), `check_rule8` and `check_no_mram_write` on both, the hardware-image gate (no console, no nPM13xx node, the panel only through the gated rails, BUCK1 expecting W21's code 0x01), `check_native.py --observe`, and wisp-ota's `pack-main` (sendable). The app embeds its git revision, so a rebuild of a later commit differs in those bytes. The first native-1 (`6a24ae47…`, stage-0b's Wisp Boot) is superseded: that Wisp Boot hangs in `boot-nor` on silicon (rung4.md W24d results).

`install-wisp` writes whole 16-byte units, so its final CRC covers the image and the 4 bytes after it, which keep what MRAM held there. Every image installed so far (stock, stage-0, stage-0b, stage-0c, native-0) leaves stock's bytes there, so the final CRC is **`ef6d2541`** in every known state. `proposed-pin.json` holds the values the pinning commit would copy (`scripts/propose_pin.py native-1`). `app-check` compares the image's own bytes with the manifest's `image_crc32`.
